# Engineering coverage and applicability acceptance

Build authorized October 21, 2026. This milestone exposes declared mission checks and existing engineering evidence; powered atmospheric flight follows separately.

User task: identify which checks need engineering work, record why a bounded model is or is not applicable, and revisit that decision after changing the design.

1. Every saved requirement appears even before coverage planning. A passing criterion with unknown physical applicability remains an applicability gap.
2. Add a check with a mission phase, discipline, applicability decision, optional requirement mapping and concrete next step. Unmapped required checks remain missing analysis.
3. Exclusion and declared model fit need an explicit rationale. Excluding a check never hides an existing unmet criterion or changes the engineering review.
4. A model outside its assumptions stays visibly outside even if its numerical criterion is met. Unsupported, uncalculated, stale and unassessed evidence stay distinguishable.
5. Changing a linked requirement, model or relevant input flags the stored declaration for review; unrelated edits do not silently rewrite it. Removed mappings remain visible.
6. Save append-only versions using the displayed context digest and base version. Conflicting edits fail without losing the form. Historical revisions and unsaved drafts are read-only.
7. Phase grouping, status/discipline filters, requirement navigation and useful scope details work on desktop and narrow screens. Phase labels never imply that a solver represents that phase.
8. Saved coverage appears in the engineering report and in its same-snapshot combined export, retaining original numerical evidence and declared exclusions.
9. No overall mission-success badge or physics-completeness percentage. User declarations are not verified engineering approval.
10. Offline tests and isolated browser checks preserve original founder records, inference settings and spending reservations. No provider connection is required.
