# Operating-envelope studies acceptance

Authorized October 23, 2026. Second of the agreed five remaining builds.

An engineer declares ranges for existing model parameters, previews the exact
Cartesian combinations and computation limits, runs the sampled study against
an exact saved baseline, and identifies worst observed requirement margins and
unresolved cases without changing canonical project findings.

- One to three explicit axes, finite ordered endpoints, two to nine points each,
  no more than sixteen combinations. Preserve exact endpoints, units, ordering
  and all sampled combinations. No hidden sampling, uncertainty distribution,
  interpolation, optimization or continuous safe-envelope conclusion.
- Requirements stay fixed. Block criterion inputs, ignored linked-only bindings
  and integration-resolution steps as axes. Other input applicability remains
  constrained by each maintained adapter and its declared numerical criteria.
- Preview executes no calculator. Work/receipt limits apply before calculations;
  explicit run saves once to existing scenario history, not a project revision.
- For each requirement, show minimum signed inequality margin or maximum absolute
  equality difference, all tied case identities, status counts and unassessed/
  overflowing margins. Never compare margins across units or hide failed cases.
- A sampled violation and unresolved cases may coexist. All-sampled-met requires
  every sampled case assessed/met with a finite meaningful margin; it is not a
  statement about untested conditions between points or omitted physics.
- Saved baseline/source identity, current context guards, append-only history,
  solver-free historical reads, visible limitations and report/JSON agreement.
- Verify independent simple arithmetic, ties, multi-axis combinations, unknown
  cases, invalid/budget/stale inputs, tampering, UI workflow and data preservation.
  Use disposable storage; no paid calls or founder fixture insertion.
