# Whole-project investigations

Build D adds a project scope beside the existing requirement Assistant. It reviews a frozen saved engineering review across related requirements, model assumptions, declared scalar dependencies, calculation/reuse origins and preceding reviewed changes. It does not run a new simulation or authorize a mission.

## Use it

1. Open 6D, select a saved project/revision and run its checks if required.
2. Choose **Investigate project** in the sidebar or toolbar. The toolbar entry is also available on narrow screens.
3. Choose **Ask what changed and what to check**, or enter a project question. Inspect the stated data-sharing scope and active model. Opening the panel makes no inference call.
4. Choose **Start live investigation** deliberately. The existing private Nebius connection and approved cumulative allowance apply. A remembered Windows connection can restore automatically; otherwise use Connect AI privately.
5. Inspect the application-owned finding table, review queue, exact changes, executed/reused models and source citations. Open a finding's disclosure for its concrete next checks. Download the saved investigation JSON when needed.
6. Switch to **Requirement** for the original focused workflow and its separate saved history/reproducibility recheck. Switching scope makes no new inference call.

The application orders unmet criteria, then unassessed criteria, then met criteria, with the declared critical flag first within each group. This is a review queue, not a quantified mission-risk ranking. A critical unknown can still require expert prioritization. Met findings remain limited to their captured configuration, models and conditions.

## Division of work

The application supplies exact canonical findings, comparisons, scalar directions, provenance and concrete requirement-specific review guidance. Nemotron reads the project, dependency and change bundles before offering qualitative next-check recommendations. The app displays exact change facts; the model must not invent quantities, directions, physical causes or launch approval. No stronger model is enabled automatically.

Full source-bound bundles remain in the saved receipt. The provider gets compact qualitative views: all requirement statuses and model scopes remain included, while repeated numeric comparisons/source pointers and full guidance stay local. The complete final request size is checked before the first reservation. Oversized projects are rejected explicitly rather than silently reviewed in part.

## Included evidence and boundaries

- The exact saved project/revision/run/review, all captured requirement findings, bounded model summaries, declared systems/interfaces and scalar links, input records, execution/reuse origins and preceding reviewed changes.
- Relevant requirement/model reference contexts pinned in one database snapshot. Existing source-context bounds disclose omitted links; linked text remains untrusted and is not independently validated.
- Up to eighty requirements and forty models, with raw context and transport-size limits. Scalar findings/model scope are reviewed; sampled trajectory arrays are not sent.
- Unselected physical-test rows, imported time-history records, scenario/envelope records and unlinked library material are excluded. Whole-project scope does not mean every artifact or every physical effect has been assessed.

There are no editing, model-switching, external retrieval or fresh-calculation tools in this scope. Use the existing requirement investigation when a supported reproducibility recheck is needed. No comparison establishes simultaneous coupled physics, complete rocket coverage or launch readiness.

## Controls and records

Each current Super job retains the existing six-request/USD0.20 reservation ceiling within the cumulative USD29.50 development approval. The normal whole-project sequence uses three reads and a finish response. Invalid actions or explanations stop the job; no automatic retries follow. A receipt keeps partial activity and rejected interpretation where available. Interrupted jobs are not restarted automatically.

The UI distinguishes live inference, offline synthetic transports and saved history. Provider-reported token usage, elapsed time, usage-based estimates at configured price ceilings, and conservative reservations are separate from actual provider billing. Incomplete token usage is marked unavailable. Source/version locks and the existing selected-model gate remain active.

Phrase guards are incomplete: they can miss semantic errors or flag acceptable wording. The observed higher-fidelity/scope false positives and a real incorrect direction claim are retained in the delivery results. Independent human engineering review remains pending.
