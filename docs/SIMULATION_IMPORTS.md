# Specialist simulation imports

Local delivery October 23, 2026, build `3eed1f8127d9`.

Open http://127.0.0.1:8768/, refresh and choose **Simulation imports** in the top
toolbar. No API key is needed. The existing **Test data** page still handles
scalar measurements; this page handles recorded time histories.

## Try the workflow

1. Click **Use constructed CSV example**. The sample is explicitly synthetic,
   unrelated to the selected project and not generated by an external solver.
2. Review its source, configuration, frame, time origin, columns and units.
   Click **Validate & preview CSV**, then **Save reviewed import**.
3. Play or scrub the recorded samples. Change the plotted channel and inspect
   exact row values. Reopen saved imports from the history picker.
4. Export the frozen receipt or print the imported record. The full project
   report includes recorded import summaries; combined JSON includes retained
   CSV, mappings, baseline and comparison evidence in the same read snapshot.

For real specialist output, export a UTF-8 CSV from that tool, choose the file
and explicitly map its time column and up to twelve quantity columns. Enter the
units and provenance yourself. No vendor-specific file parser, automatic unit
conversion, CAD ingestion or specialist solver execution is implied.

## Optional comparison with a project calculation

Run the project's checks first. Choose an orbital or powered-flight project
model, map supported baseline fields and check **Capture a comparison with the
current saved project run**. Declare configuration/conditions, frame and time
origin explicitly. Supply an absolute agreement tolerance for each compared
channel. Validate and save again after edits.

Supported orbital fields are Cartesian position/velocity components, radius and
speed. The exact frame is `body_centered_inertial_3d`; units are `m` or `m/s`.
Powered-flight fields include altitude, signed vertical velocity, mass, dynamic
pressure, signed acceleration, thrust and drag. Its frame is
`radial_vertical_above_launch_surface`. Compared time histories use seconds from
`model_start`. These labels state comparison conventions, not independently
verified external-tool settings.

Only exact timestamps align. Different units, frame, origin or undeclared matching
conditions leave a comparison unassessed. Missing canonical numerical support,
missing tolerances and no overlap also remain unassessed. Partial timestamp
overlap is labelled partial; it cannot produce a whole-history agreement pass.
At a discontinuous event, differing before/after values at one timestamp require
an explicit event-side representation beyond this version; no side is guessed.

Generic channels can be saved without a model or baseline for replay. Their
comparison remains unassessed. Mapped position components support XY/XZ/YZ
projections; time plots use independent vertical ranges. Plot overviews can be
decimated, but selected values always refer to exact retained rows. Connecting
points is a visual aid, not numerical interpolation.

## Retention and limits

Imports are append-only and bound to a saved project revision. A compared import
freezes its exact canonical run. Reruns, changed revisions and source updates
flag historical context without rewriting it. Reads verify recorded arithmetic
and digests without calling an ODE solver. Historical revision/draft views cannot
save a new import. Unsigned digests are consistency checks, not authentication.

CSV bounds: 4 MiB, 2–16,385 numeric rows, 32 columns, 12 mapped channels and 4,096
characters per cell. Times must be nonnegative and strictly increasing. Mapped
cells must be finite decimal/scientific numbers; expressions, unsafe integer
values, underflow/subnormal values and malformed rows are rejected. Time units
must be seconds; there is no implicit conversion. Source CSV text is retained.

List/report history is bounded to twenty whole records. Combined import snapshots
also have a 64 MiB record budget and expose omissions; the total combined review
has its existing 64 MiB limit. Individual receipt exports remain available for
records omitted from the summary.

Imported data and matching declarations remain unverified. Agreement does not
validate the underlying physics or change canonical requirement findings. This
adds evidence intake and comparison, not complete rocket physics or mission
authorization. Future implementation changes must preserve these schema-v1
reading and comparison semantics for historical receipts.
