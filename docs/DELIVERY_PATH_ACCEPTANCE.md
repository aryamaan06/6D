## First build: application-owned numerical roles

- The app binds the calculated metric, declared limit, each recorded grid pair,
  accuracy criterion, selected test quantities and reproduction result to exact
  saved pointers. A metric cannot be supplied as a limit by the model.
- The model provides qualitative interpretation and next checks. It no longer
  copies quantities or selects opaque numerical IDs. The final action contains
  short examples and an explicit words-only contract.
- New model-visible numerical payload values are withheld with an explicit
  disclosure. Full evidence remains captured locally, with source hashes and
  exact values visible in deterministic views; no canonical calculation changes.
- Unknown inline references, raw numerical commentary, forged role bindings and
  known status/guarantee errors remain rejected. This does not prove general
  semantic correctness, physical validity or complete applicability.
- Replay the actual rejected responses without changing their historical
  receipts. Keep the older reference policy and comparison reports readable.
- Verify offline positive/negative cases and API boundaries before proceeding
  to the next build. Paid verification has separate enforced bounds and requires
  the private connection; no automatic retries or stronger-model activation.

## Second build: guided first use

- A visible guided-review control connects reference-template intake, baseline
  checks, explicit draft editing, change review, save/rerun and evidence export.
- Guidance follows real saved/draft/review states. Drafts, stale evidence and
  unreviewed revisions cannot look complete. Controls reuse the existing workflow.
- No automatic project import, saving, calculation or inference is triggered by
  opening the guide. A sample is clearly constructed, not a flight mission.
- Verify a complete baseline → changed input → saved revision → targeted review
  → report journey in an isolated store. Existing founder records stay unchanged.
- Keyboard access, empty/error states and a narrow viewport remain usable.
