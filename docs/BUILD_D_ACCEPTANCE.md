# Build D acceptance: whole-project investigations

Outside-user task: after calculating a saved design revision, ask what changed, which recorded criteria/gaps deserve review, and which engineering checks should happen next. Inspect citations without losing the existing requirement investigation workflow.

- Frozen project/revision/run/review identity; verify integrity and current calculation sources before inference and after each response.
- Read all saved findings, model/dependency/reuse summaries and prior reviewed changes before allowing a cited finish. No hidden rerun, threshold edits or external retrieval.
- Application-owned canonical finding table, deterministic review queue (not a failure-risk ranking), concrete requirement-specific next checks and exact change directions. AI supplies qualitative interpretation only.
- Require complete bundle citations; reject literal quantities, unsupported direction/causality and launch approval language. Preserve failed/rejected runs. These guards cannot prove semantic correctness.
- Pin linked requirement/model references in one database snapshot. Disclose omissions and excluded observations/imports/studies; no claim of every project artifact being analyzed.
- Retain current selected-model gate, cumulative USD29.50 approval and per-job reservation/request limits; no automatic retries, stronger-model activation or paid calls on navigation.
- UI offers project versus requirement scope, consent, saved history, source records, actual model/provider/live state, latency, token usage and reservation-based cost clearly separated from actual billing.
- Verify mixed met/unmet/unassessed, prior-change/reuse, missing/stale/tampered evidence, prompt injection, invalid tools/citations and frozen history. Verify requirement regression and actual browser interactions.
- Offline transports, live qualification and human review are distinct. A new live pack must be explicitly recorded; no inherited qualification of this new workflow.

No application code can establish complete physical validity, mission readiness, user demand or a guaranteed score. D does not add another physics model or start E/F.
