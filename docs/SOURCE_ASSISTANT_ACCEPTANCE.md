# Source-connected Assistant acceptance

The user task is to explain one saved engineering finding using its recorded calculation and relevant references, inspect the captured context, optionally find and review another reference, and track unresolved work without changing the numerical finding.

1. Capture the saved review and relevant requirement/finding/model-assumption source links in one database read snapshot. Exclude unrelated targets. Keep source/link versions, digests, content, review flags, scope and omissions.
2. Preserve the queued snapshot when a source, link or project changes later. Historical investigations do not acquire current references. Unsupported or absent sources stay explicit gaps.
3. Pass references as untrusted supplemental context through the existing bounded investigation. Source text cannot issue instructions, trigger searches, supply quantitative findings, replace criteria or clear unassessed scope. No extra tool turn or automatic inference is introduced.
4. Show captured references separately from numerical evidence and qualitative AI commentary. Preserve the canonical finding, existing application-owned numerical roles, direction checks and prior failed investigation records.
5. Offer a source-focused question for the selected requirement and a scoped path to the existing engineering-action queue. Historical context cannot create an action pretending to represent the current finding.
6. Open optional research within the source-library workflow. Connect a private memory-only Tavily key without searching. Show an explicit cumulative application credit ceiling, reservation count and remaining capacity; reconnecting never resets consumed reservations.
7. Send only the explicitly entered query on a deliberate Basic search. Use fixed provider options, one request, no retry and a prospective one-credit reservation. No automatic project upload, URL fetch, extraction, crawl or generated-answer request.
8. Refuse draft/historical writes, changed library digests, invalid targets, absent connections and exhausted credits before transport. Bound response size, timeout, URLs, field lengths and JSON parsing; sanitize provider failures and never echo keys.
9. Save request/result receipts separately, with original project/revision/target/query/options/time/usage identities and controlled failure records. Preserve failed reservations. Viewing history is read-only and never reruns a search.
10. Preview a returned title, URL and excerpt as unverified search material. Explicitly copying a preview fills the existing source form only. Saving the source and linking it remain separate deliberate actions; neither changes calculations or findings.
11. Prevent late search/catalogue/preview responses from changing another project or replacing newer choices. Clear credential inputs immediately and keep them out of browser storage, exports, logs and receipts. Render text and URLs safely at desktop and 390px widths.
12. Verify the full workflow with controlled providers and isolated databases. Existing founder rows, source/action records, runs, model selections, Nebius spending allowance and historical artifacts must remain unchanged. Live Tavily/Nebius qualification requires a separate connected, bounded run; offline acceptance is labelled honestly.

LangSmith tracing is a following milestone. No authentication, automatic engineering approval, external-source authenticity or broad semantic correctness is claimed here.
