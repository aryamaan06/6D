## Why Nano was used first

That integration is now verified on two constructed orbital cases and, separately on October 16, on a supported thermal and unsupported GNC project investigation.

This does not establish Nano as the best model for general project investigation, nor does it justify using Nano for every task. The earlier work tested protocol integration, not a comparative model-quality benchmark.

## Evaluation before production routing

1. Prepare a fixed task set with known expected results and held-out variations: input/unit extraction, requirement conflicts, explicit dependency changes, selecting a useful supported check, acknowledging missing evidence and citing recorded results.
2. Establish the Nano baseline, then compare Super and Ultra on identical tasks/tools/evidence. Separate workflow quality from physics-tool correctness.
3. Validate each candidate's exact request/response schema, tool calling, reasoning controls, token limits and error behavior offline where possible. A provider listing is not an exact-protocol pass.
4. Run one bounded comparison batch through the existing private helper once the implementation and metadata are ready. Do not ask Arya to conduct serial profile experiments.
5. Record task success, missed issues, unsupported claims, citation accuracy, invalid calls, latency and token/cost usage. Preserve failures and abstention.
6. Select and document the standard and deep-investigation models. Keep manual override/context visible; escalation uses explicit complexity signals or detected evidence gaps, not unsupported self-reported confidence.
7. Limit escalation and calls. No silent fallback, repeated retry loop or automatic extra spend. A missing physical model remains missing regardless of model size.

## What models do versus engineering tools

Models interpret supplied material, ask for missing information, plan supported investigations, connect explicit evidence and explain findings. The engineering kernel/specialist solvers calculate results and compare criteria. A larger language model does not create a validated GNC/CFD/thermal solver, physical-test record or flight-readiness determination.
