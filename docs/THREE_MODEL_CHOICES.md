# Choose the model for an investigation

Build 2, October 25, 2026. Nano, Super and Ultra are explicit per-investigation choices in both the requirement Assistant and whole-project Assistant. They do not change the engineering solver or the saved finding.

1. Open a saved project/revision and calculate its supported checks if necessary.
2. Choose **Investigate project**, or select a requirement in Systems workspace and open **Assistant**.
3. Under **Investigation model**, choose Nano, Super or Ultra. Read the role description and enter your question. Selection makes no request and does not erase the question.
4. Choose **Start live investigation** to send the scoped evidence using that exact model. The model cannot change canonical findings. No automatic escalation, fallback or retry occurs.
5. The saved investigation records the model actually used. Choosing another model afterward does not relabel history. While any investigation runs, the selector and Start remain unavailable; status refreshes automatically until the job finishes.

The proposed roles are lightweight/narrow questions (Nano), standard investigation (Super) and detailed related-findings review (Ultra). These descriptions are intended usage guidance, not a general benchmark ranking. Small constructed development checks do not establish aerospace expertise or universal semantic correctness.

## Accounting and defaults

Each investigation permits at most six requests. Reservation ceilings are Nano USD0.10, Super USD0.20 and Ultra USD0.35, inside the same existing cumulative approval/ledger. Failed requests retain their reservations. An explicit choice changes only allowlisted model/price fields of that approved configuration. It never changes the endpoint, approval identity, cumulative allowance, keys or protocol. The default remains the previously selected Super; no user choice promotes a new default or rewrites its historical selection proof.

The displayed application allowance is not the provider wallet. Provider-reported usage estimates and conservative reservations are not an invoice. The separate owner accounting-display refinement remains pending; this milestone does not increase the allowance to the reported Nebius balance.

Hosted deployments retain the operator's configuration and cumulative/day/session limits, with live AI disabled unless separately configured. Choosing a model grants no access to operator credentials or administrative controls.

## Protocol and readability

Read-only action schemas explicitly constrain read citations to an empty array and read commentary to an empty string. Nonempty read payloads are still rejected; invalid model output is not silently repaired. The historical Nano rejection did not retain its full raw argument body, so the offending field cannot be reconstructed.

Body text is 14.5px. Essential small copy, badges, identity strings and numerical readouts are generally at least 13px; fields are 14px on desktop and 16px on narrow screens. Larger findings retain their hierarchy. Canvas labels also use 13px, with fewer time-axis ticks on narrow charts. Native local fonts, contrast, navigation and print-specific styling remain in place.
