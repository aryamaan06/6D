# Workspace navigation and typography — acceptance

Authorized October 25, 2026: Build 1 and the founder's Apple × Notion typography specification. This updates access to existing capabilities; three-model selection, accounting-display redesign and later interface refinements remain separate.

An outside reviewer must be able to open Projects, choose a project, choose a work area and open a relevant tool without navigating an undifferentiated list. The selected project, saved revision and view must remain apparent.

Acceptance before delivery:

- Project landing, five work areas, contextual destinations and meaningful breadcrumbs preserve access to every existing tool and example.
- Browser Back/Forward, in-app Back, direct view URLs and refresh restore the selected project/revision/view and item context. URLs contain navigation identifiers only, never drafts, credentials or AI questions.
- Same-project navigation preserves the shared draft. Switching saved project/revision or leaving the application protects unsaved edits; declining navigation retains edits and the current route.
- Navigation never starts inference, a search, metrics upload or numerical calculation. Existing explicit run/save/AI actions retain their gates.
- Native sans/mono fallbacks, heading tracking, off-white surfaces and subtle borders apply consistently without external font requests. Small data remains readable and essential secondary text retains usable contrast.
- Desktop and narrow viewport paths have no unintended horizontal overflow, inaccessible destinations or browser errors.
- Verify using an isolated database and constructed records; preserve the founder's projects, credentials and spending records. Record actual results, restart the served build and publish only privacy-checked source/tests/docs.
